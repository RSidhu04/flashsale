# Repeat benchmark — 2026-10-31

Reran the same 18 measured workloads without changing application code, retry budget, load settings or runner. All 30 local test executions passed before measurement. Original results remain available in [the first report](RESULTS.md).

Source: [`c21ddf1`](https://github.com/RSidhu04/flashsale/commit/c21ddf13021e9948f840beaa4cf2c9727777ab99); clean working tree at measurement start.

Environment: same Apple M5 development host; PostgreSQL 14.22 x86_64 on ARM, Java 21.0.13, k6 2.3.0, 512 MiB heap, Hikari pool 16 and database durability enabled. Three rounds, 100 virtual users, 10,000 attempts per workload, 2,000 excluded warmup attempts per process. These are short local bursts, not sustained production capacity tests. See [environment](2026-10-31/environment.json) and [test counts](2026-10-31/test-counts.json).

## Interpretation

All 180,000 measured attempts completed; every workload conserved stock and had zero unexpected HTTP responses. There were 150 explicit optimistic retry-exhaustion 503s. The recorder retains failed availability thresholds and exits 2 rather than reporting a completely successful benchmark.

The repeat checks the same correctness and contention tradeoffs. Exact throughput and latency vary on a shared development host; do not replace the original evidence with only the faster rerun or treat two short local sessions as a production guarantee. Each raw k6 summary has a corresponding SQL verification snapshot. Warmups are preserved but excluded from the reported measurements.
